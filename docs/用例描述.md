## 用例一：执行备份

| 项目 | 内容 |
|---|---|
| **用例标识** | UC-001 |
| **用例名称** | 执行备份（Execute Backup） |
| **创建人** | — |
| **创建日期** | 2026-07-10 |
| **语境目标** | 用户通过命令行指定要备份的源目录和备份文件存放位置，系统自动遍历源目录下的所有子目录和文件，根据用户设定的筛选条件、压缩方式和加密方式，将符合条件的文件连同目录结构一并打包为单个备份文件。 |
| **前置条件** | 1. 用户已打开命令行终端；2. 要备份的源目录存在且用户对其有读取权限；3. 备份文件所要存放的位置有写入权限；4. 若选择了数据加密，用户须提供密码。 |
| **成功的结束状态** | 生成一个完整的备份文件，其中包含所有符合条件的文件内容、目录结构和文件属性信息（如权限、时间戳等），备份文件内部具备版本标识和完整性校验信息，可供后续还原使用。 |
| **失败的结束状态** | 1. 源目录不存在或无法读取，操作终止并提示错误；2. 备份文件存放位置无法写入，操作终止；3. 用户提供的筛选条件存在矛盾（如最小尺寸大于最大尺寸），操作终止；4. 选择了加密但未提供密码，操作终止；5. 未选择加密却提供了密码，操作终止；6. 指定的压缩或加密算法不被系统支持，操作终止。 |
| **参与者** | 用户、文件系统 |
| **触发器** | 用户在命令行输入备份命令，指定源目录和备份文件路径并回车。 |
| **基础用例** | 无（顶层用例） |
| **包含用例** | 无 |
| **扩展用例** | 过滤文件、压缩数据、加密数据 |
| **事件流** | **基本流程** |
| | **一、命令解析与参数检查** |
| | 1. 用户输入备份命令及各项参数。 |
| | 2. 系统解析命令行中的所有参数：运行模式、源目录路径、备份文件路径、压缩方式、加密方式、密码，以及各项筛选条件。 |
| | 3. 系统确认运行模式为"备份"。 |
| | 4. 系统检查用户输入的筛选条件是否合法（如尺寸范围是否合理、时间格式是否正确、是否在正确的模式下使用筛选等），不合法则进入扩展流程第1步。 |
| | 5. 系统根据用户指定的算法名称，查找并准备对应的压缩和加密处理模块。若算法不存在则进入扩展流程第2步。 |
| | **二、路径校验** |
| | 6. 系统检查源目录确实存在且为目录（而非普通文件），不满足则进入扩展流程第3步。 |
| | 7. 系统对路径进行安全检查：禁止使用绝对路径和包含".."的相对路径，防止备份文件在还原时被恶意利用写入到目标目录之外，违反则进入扩展流程第4步。 |
| | **三、备份准备工作** |
| | 8. 系统搭建数据处理流水线：原始文件 → 压缩处理（如启用）→ 加密处理（如启用）→ 写入备份文件。当同时启用压缩和加密时，系统先用临时文件完成压缩，再对压缩结果进行加密。 |
| | 9. 系统创建备份文件的写入模块，准备开始写入。 |
| | 10. 系统在备份文件开头写入文件头信息，包括：文件类型标识（表明这是一个备份系统生成的归档文件）、格式版本号（用于未来兼容升级）、以及本次使用的压缩和加密方式名称。 |
| | 11. 系统将源目录本身作为第一条目录记录写入备份文件。 |
| | **四、目录遍历与文件备份** |
| | 12. 系统从源目录开始，逐层遍历所有子目录和文件，遍历异常时进入扩展流程第5步。 |
| | 13. 遇到子目录时：将该目录的信息（路径、权限、时间戳等属性）写入备份文件，并继续进入该目录遍历其内容。目录本身始终会被遍历，不受文件筛选条件影响，以避免因父目录被跳过而导致其内部文件被遗漏。 |
| | 14. 遇到普通文件时： |
| | 14a. 先判断该文件是否满足用户指定的所有筛选条件（路径、文件名、大小、修改时间），不满足则跳过。 |
| | 14b. extend:: 过滤文件 — 按用户设定的条件筛选要备份的文件。 |
| | 14c. 计算文件的原始大小，并对文件内容生成校验码（用于还原后验证数据是否正确恢复）。 |
| | 14d. extend:: 压缩数据 — 若用户选择了压缩，对文件内容进行压缩处理。 |
| | 14e. extend:: 加密数据 — 若用户选择了加密，对文件内容进行加密处理。 |
| | 14f. 将处理后的数据写入备份文件，同时记录文件在备份文件中的存储大小、原始大小、存储校验码（用于检测备份文件本身是否损坏）、内容校验码（用于检测还原后内容是否正确）以及文件属性信息。 |
| | 15. 当前版本不支持符号链接、设备文件等特殊文件类型，遇到此类文件会跳过。 |
| | 16. 所有目录和文件遍历完毕后，系统在备份文件末尾写入结束标记。 |
| | 17. 系统输出"备份成功完成"的提示信息。 |
| | **扩展流程** |
| | 1. 运行模式既不是"备份"也不是"还原"→ 提示错误，显示命令使用说明后退出。 |
| | 2. 筛选条件不合法（如最小尺寸大于最大尺寸、开始时间晚于结束时间）→ 提示具体错误后终止。 |
| | 3. 在还原模式下使用了筛选参数（筛选仅对备份生效）→ 提示错误后终止。 |
| | 4. 指定的压缩算法名称系统不支持 → 提示"未知的压缩算法"后终止。 |
| | 5. 指定的加密算法名称系统不支持 → 提示"未知的加密算法"后终止。 |
| | 6. 源目录路径不存在 → 提示"源目录不存在"后终止。 |
| | 7. 源路径存在但不是目录（如指向了普通文件）→ 提示"源路径不是目录"后终止。 |
| | 8. 路径使用了绝对路径格式（以"/"开头）→ 拒绝，防止攻击者构造包含绝对路径的备份文件在还原时覆盖系统文件。 |
| | 9. 路径中包含了".."（上级目录引用）→ 拒绝，防止还原时文件被写入到目标目录之外。 |
| | 10. 遍历过程中遇到无法访问的文件或目录（如权限不足）→ 终止备份并提示错误。 |
| **非功能需求** | 1. 性能：目录遍历时间与文件数量成正比；2. 安全性：路径安全检查防止目录穿越攻击；3. 可扩展性：压缩、加密、筛选均采用可替换的模块化设计，新增算法无需改动核心流程；4. 可靠性：对每个文件生成双重校验码，确保数据在存储和还原两个环节的完整性。 |
| **补充规格说明书** | 参见 [README.md](../README.md) 第 5 节各模块实现原理。 |

## 用例二：执行还原

| 项目 | 内容 |
|---|---|
| **用例标识** | UC-002 |
| **用例名称** | 执行还原（Execute Restore） |
| **创建人** | — |
| **创建日期** | 2026-07-10 |
| **语境目标** | 用户通过命令行指定之前生成的备份文件和要还原到的目标目录，系统读取备份文件，验证其合法性，按原有结构重建目录树、恢复所有文件内容和属性信息。 |
| **前置条件** | 1. 用户已打开命令行终端；2. 备份文件存在且可读；3. 还原目标目录的上级目录存在且可写；4. 若备份时使用了加密，用户须提供正确的密码；5. 用户指定的压缩和加密方式须与备份时使用的一致。 |
| **成功的结束状态** | 在目标目录下完整还原原有的目录结构和所有文件，文件内容与备份时完全一致（通过内容校验码验证），文件的权限、属主、时间戳等属性也已恢复。 |
| **失败的结束状态** | 1. 备份文件不存在或无法读取，操作终止；2. 备份文件格式不合法（文件类型标识不匹配、版本不支持、内部记录格式异常），操作终止；3. 用户指定的压缩或加密方式与备份文件中记录的不一致，操作终止；4. 密码错误导致解密失败或内容校验不通过，操作终止；5. 目标路径无法写入，操作终止；6. 备份文件内容被损坏或篡改（存储校验码不匹配或文件末尾有多余数据），操作终止。 |
| **参与者** | 用户、文件系统 |
| **触发器** | 用户在命令行输入还原命令，指定备份文件路径和目标还原目录并回车。 |
| **基础用例** | 无（顶层用例） |
| **包含用例** | 无 |
| **扩展用例** | 压缩数据、加密数据 |
| **事件流** | **基本流程** |
| | **一、命令解析与准备工作** |
| | 1. 用户输入还原命令及参数。 |
| | 2. 系统解析参数，确认运行模式为"还原"，不符合则进入扩展流程第1步。 |
| | 3. 系统确认还原模式下未使用筛选参数（筛选仅对备份生效），若使用了则进入扩展流程第2步。 |
| | 4. 系统根据用户指定的算法名称，准备对应的解压和解密模块。 |
| | 5. 系统搭建反向数据处理流水线：备份文件 → 解密（如有）→ 解压（如有）→ 原始文件。 |
| | 6. 系统创建备份文件读取模块和还原引擎，开始还原流程。 |
| | **二、备份文件合法性检查** |
| | 7. 系统读取备份文件头部信息进行校验：确认是合法的备份文件格式（文件类型标识正确）；确认版本号在当前系统的支持范围内；确认文件头中各项标志位合法。格式异常时进入扩展流程第3步。 |
| | 8. 系统读取备份文件中记录的压缩和加密方式名称，与用户命令行指定的进行比对。若不一致则进入扩展流程第4步，防止用错误的解压或解密方式处理数据。 |
| | **三、路径安全检查** |
| | 9. 还原每个文件或目录前，系统检查其在备份文件中存储的路径：禁止包含".."（防止文件被还原到目标目录之外）；禁止使用绝对路径（防止覆盖系统文件），违反则进入扩展流程第5步。 |
| | **四、逐条还原** |
| | 10. 系统依次读取备份文件中的每条记录： |
| | 10a. 第一条记录必须是根目录，否则判定备份文件格式异常，进入扩展流程第6步。 |
| | 10b. **目录记录**：在目标目录下创建对应的子目录（已存在则跳过）；将该目录的属性信息（权限、属主、时间戳等）暂存到延迟列表中，等所有子文件还原完成后再统一设置——因为创建子文件的过程会更新目录的时间戳，若立即设置会被覆盖。目录记录格式异常时进入扩展流程第7步。 |
| | 10c. **文件记录**：路径不能为空也不能是根目录，否则进入扩展流程第8步。创建目标文件，将备份文件中的数据通过解密和解压模块还原为原始内容写入磁盘；写入完成后比对新文件的大小和内容校验码是否与备份时记录的一致。extend:: 压缩数据、extend:: 加密数据 在此步骤参与解压和解密。大小或校验码异常时进入扩展流程第9步。 |
| | 10d. **结束标记**：该标记的元数据应全部为零，其后不应再有其他数据，异常时进入扩展流程第10步。系统停止读取。 |
| | **五、恢复文件属性** |
| | 11. 每个文件内容恢复后，立即应用其原始属性： |
| | 11a. **权限**：将文件的读写执行权限恢复为备份时的状态。 |
| | 11b. **属主和属组**：恢复文件的所有者和所属用户组。若当前用户不是系统管理员，此项操作可能因权限不足而失败——此时系统会自动跳过，不影响其他内容的正常还原；若因其他原因失败则进入扩展流程第11步。 |
| | 11c. **时间戳**：将文件的最后访问时间和最后修改时间恢复为备份时的值。 |
| | **六、目录属性延迟恢复** |
| | 12. 所有文件和目录记录处理完毕后，系统按从深到浅的顺序（深层子目录优先）对暂存的目录统一设置属性。这样做的原因是：深层子目录在还原过程中是最后被创建的，但其属性应优先恢复；如果先恢复上层目录的修改时间，之后创建子目录时会再次更新上层目录的时间戳，导致其原始时间丢失。 |
| | 13. 系统输出"还原成功完成"的提示信息。 |
| | **扩展流程** |
| | 1. 运行模式不是"还原"→ 提示错误，显示命令使用说明后退出。 |
| | 2. 还原模式下使用了筛选参数 → 提示"筛选仅对备份有效"后终止。 |
| | 3. 文件类型标识不匹配 → 提示"无效的备份文件格式"后终止。 |
| | 4. 版本号不在支持范围内 → 提示"不支持的备份文件版本"后终止。 |
| | 5. 文件头含未知标志位 → 提示错误后终止。 |
| | 6. 压缩方式名称不一致 → 提示"压缩方式不匹配"，防止用错解压方式。 |
| | 7. 加密方式名称不一致 → 提示"加密方式不匹配"，防止用错解密方式或将未加密文件误当加密文件处理。 |
| | 8. 路径包含".."→ 拒绝还原，防止目录穿越攻击。 |
| | 9. 首条记录不是根目录 → 判定备份文件格式异常，终止还原。 |
| | 10. 目录记录中包含了不应有的数据负载 → 判定格式异常，终止还原。 |
| | 11. 文件记录的路径为空或为根目录 → 判定格式异常，终止还原。 |
| | 12. 还原后文件大小与备份时记录的不一致 → 提示错误（说明解码过程出了问题），终止还原。 |
| | 13. 还原后文件内容校验码不匹配 → 提示错误后终止。最常见的原因是密码错误导致解密出了错误数据，也可能是备份文件在传输或存储过程中损坏。 |
| | 14. 备份文件存储校验码不匹配 → 提示错误（说明备份文件本身已损坏），终止还原。 |
| | 15. 结束标记的元数据不全为零 → 判定格式异常，终止还原。 |
| | 16. 结束标记之后还有额外数据 → 提示"备份文件末尾存在多余数据"（文件可能被篡改），终止还原。 |
| | 17. 设置属主/属组时因权限不足失败 → 自动跳过，不影响其他内容的还原（普通用户也能正常使用还原功能）。 |
| | 18. 设置属主/属组时因其他原因失败 → 终止还原并提示错误。 |
| **非功能需求** | 1. 安全性：路径检查防止目录穿越；密码错误不会输出错误数据（由内容校验码和加密认证双重保障）；2. 可靠性：对备份文件本身和还原后内容分别进行校验，可区分"存储损坏"和"解码错误"两类不同问题；3. 容错性：非管理员用户还原时属主设置失败自动跳过，不影响正常使用；4. 正确性：目录属性延迟恢复机制确保还原后的目录时间戳与备份时一致。 |
| **补充规格说明书** | 参见 [README.md](../README.md) 第 5.1、5.2、5.7、10.1 节。 |

## 用例四：过滤文件

| 项目 | 内容 |
|---|---|
| **用例标识** | UC-004 |
| **用例名称** | 过滤文件（Filter Files） |
| **创建人** | — |
| **创建日期** | 2026-07-10 |
| **语境目标** | 用户在备份时通过命令行指定筛选条件，系统对每个文件进行判断，只有满足所有条件的文件才会被备份。支持四类筛选条件：按文件路径、按文件名、按文件大小、按修改时间。不同类型的条件之间是"全部满足"的关系，同一类型的多个条件之间是"满足其一即可"的关系。筛选仅对备份操作生效，目录不受筛选影响（始终遍历）。 |

| | 1. 系统读取用户指定的压缩算法参数（如未指定则默认为"不压缩"）。 |
| | 2. 系统在压缩算法注册表中查找该算法名称，找到后创建对应的压缩处理模块实例。若算法不存在则进入扩展流程第1步。 |
| | **二、流水线处理** |

| | **三、可用的压缩算法** |
| | 6. **不压缩（none）**：默认选项。不对文件内容做任何变换，数据原样存储。备份文件头部记录为"不压缩"。 |
| | 7. **游程编码（RLE）**：一种最基础的压缩方式。将连续重复出现的相同字节替换为"重复次数+字节值"，对包含大量重复内容的数据（如图片、填充区）有一定压缩效果。该方法算法简单、速度极快，是本系统中用于验证压缩接口可扩展性的原型算法，实际压缩率有限，对复杂数据（如已压缩文件、加密数据）可能反而会使体积变大。 |
| | 8. **霍夫曼编码（Huffman）**：一种经典的统计压缩方法。先对文件进行一次完整扫描，统计每种字节值出现的频率；然后自动构建一棵"最优编码树"——出现频率越高的字节用越短的编码表示，频率越低的用越长的编码。对文本类文件（字节频率分布不均）有较好的压缩效果；对分布均匀的数据（如已加密内容）效果有限。由于需要在备份文件中存储编码表，对于极小的文件（几十字节），编码表本身的开销可能超过压缩节省的空间。 |
| | 9. **字典编码（LZ77）**：一种基于"查重"的压缩方法。在文件中滑动一个固定大小的窗口，发现与之前内容重复的片段时，不重复存储该片段，而是记录"往前多少字节、复制多长"的引用。对于包含大量重复文本的文件（如日志、代码）效果较好。窗口大小为 4096 字节，适合发现近距离的重复。 |
| | 10. **Burrows-Wheeler 变换（BWT）**：当前系统中压缩率最高的算法。它不直接压缩数据，而是对数据进行一种巧妙的重新排列（将所有循环旋转按字母序排列后取最后一列），使得相同的字符趋向于聚集在一起，然后配合前移编码和霍夫曼编码实现高压缩率。对较大的文本文件效果尤为显著（例如 22KB 的重复文本可压缩至约 5KB，节省约 77% 的空间）。对于极小文件，由于需要存储辅助信息（约 2KB），压缩收益有限甚至可能为负。 |
| | **扩展流程** |
| | 1. 算法名称在注册表中未找到 → 提示"未知的压缩算法"后终止。 |
| **非功能需求** | 1. 可扩展性：增加新压缩算法只需：实现压缩和解压两个核心方法，然后在算法注册表中登记一行（算法名称→创建函数），命令行和备份引擎均无需修改；2. 性能：当前同时使用压缩和加密时采用临时文件中转的方式，后续可优化为完全内存流式处理，消除磁盘中转开销。 |
| **补充规格说明书** | 当前可用算法：不压缩、游程编码（RLE）、霍夫曼编码（Huffman）、字典编码（LZ77）、Burrows-Wheeler变换（BWT）。详见 [README.md](../README.md) 第 2.4、5.3、5.4 节。 |

| | **扩展流程** |

| | 3. 算法名称在注册表中未找到 → 提示"未知的加密算法"后终止。 |
