# 白箱构件图（White-box Component Diagram）画法指南

## 一、概念与定位

UML 构件图分为两种视角：

| 视角 | 关注点 | 粒度 |
|------|--------|------|
| **黑箱** | 构件对外提供的接口和依赖 | 只看外部契约 |
| **白箱** | 构件内部子构件及其协作关系 | 展开内部结构 |

白箱构件图 = 打开一个构件的"壳"，展示其内部子构件如何通过接口、端口连接协作。

与类图的关系：白箱图解决"模块如何分拆和协作"，类图解决"每个模块内部如何设计"。一个构件可对应多个类，两种图互补，不要在一张图里混画。

---

## 二、核心图元

### 2.1 构件（Component）

外部构件用矩形 + `<<component>>` 构造型。白箱展开时，内部子构件嵌套在父构件矩形内。

```
┌─────────────────────────────────────┐
│ <<component>>                        │
│ 订单处理模块                          │
│                                      │
│  ┌──────────┐  ┌──────────┐         │
│  │ 子构件A   │  │ 子构件B   │         │
│  └──────────┘  └──────────┘         │
└─────────────────────────────────────┘
```

### 2.2 接口（Interface）

- **提供接口（Provided）**：棒棒糖记法 `○──`，表示该构件对外提供的能力
- **请求接口（Required）**：插座记法 `──(`，表示该构件依赖的外部能力

```
提供接口                    请求接口
      ○── IOrderService     ──────( IPaymentGateway
```

- 接口命名：语义明确、职责单一、与业务语言对齐（如 `IOrderValidator`，不要 `IService`）
- 复杂场景可展开为 `<<interface>>` 完整矩形，列出方法签名

### 2.3 端口（Port）

构件边界上的小矩形，接口（棒棒糖/插座）挂在端口上。命名格式：`portName: Type`。

- 简单场景直接挂棒棒糖/插座，不必使用端口
- 当一个构件有多个同类接口、需要明确"交互点"时使用端口

### 2.4 委托连接器（Delegate Connector）

虚线箭头从外部端口指向内部子构件的接口，表示"外部请求委托给哪个内部构件处理"。

```
      ○── IAPI（外部端口）
      │ 虚线 ↓
   ┌──○── IAPI（内部子构件提供的接口）
```

**注意方向**：外部端口 → 内部实现，方向容易画反。

### 2.5 组装连接器（Assembly Connector）

子构件之间的实线，棒棒糖对插座，表示提供接口满足请求接口。

```
┌──────┐          ┌──────┐
│ CompA│  ──────( │CompB │
│   ○──│──────────│      │
└──────┘          └──────┘
```

- 实线，通常不需要箭头
- 只连接棒棒糖和插座匹配的一对

## 三、画法步骤

1. **确定构件职责边界**：对外提供什么？依赖什么？核心职责？
2. **分解内部子构件**：按分层、功能模块或管道/过滤器拆分
3. **识别接口**：为每个子构件定义提供和需要的接口
4. **画出父构件框架**：矩形 + `<<component>>` 构造型
5. **放置子构件和端口**：在父构件内部画出子构件，在边界上画端口
6. **连线**：委托连线（外部端口 → 内部）、组装连线（内部 ↔ 内部）
7. **标注和审查**：检查接口归属、连线方向、无遗漏依赖

---

## 四、注意事项

### 4.1 不混用黑箱和白箱

白箱图内部必须充分展开，不应只有一个子构件。不需要展开则用黑箱图。

### 4.2 委托连线方向

从外部端口指向内部实现，含义："外部对我的调用，实际由此子构件处理"。

### 4.3 接口粒度合理

- 太粗：一个接口 50 个方法
- 太细：每个方法一个接口
- 适中：按职责聚合，每个接口 5-8 个方法

### 4.4 依赖方向符合架构原则

请求接口（插座）指向依赖方向，提供接口（棒棒糖）指向被依赖方向。

### 4.5 嵌套不超过 2 层

推荐：父构件 → 子构件。更深层次单独画图。

### 4.6 图表干净度

- 子构件不能是"孤岛"（无连线）
- 每根连线有明确语义
- 不混入类图元素（继承/关联/属性类型）

## 五、检查清单

- [ ] 父构件的外部接口（提供/需求）都已标注
- [ ] 内部每个子构件的接口都已明确
- [ ] 所有提供接口都有对应的需求接口
- [ ] 委托连线方向正确（外部端口 → 内部）
- [ ] 组装连线都有明确意图
- [ ] 没有孤立子构件
- [ ] 接口命名符合业务语义
- [ ] 嵌套深度 ≤ 2 层
- [ ] 未混入类图元素
